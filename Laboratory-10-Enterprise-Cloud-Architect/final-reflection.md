# Final Reflection — Mission 1 to Mission 10

## My Cloud Computing Journey

Completing Missions 1 to 10 in CCM101 – Cloud Computing has been a challenging but meaningful learning experience for me. At the beginning, cloud computing felt like a topic that was mostly about using online services and storing information on remote servers. As I progressed through the missions, I realized that cloud computing is much broader. It involves infrastructure, operating systems, networking, security, containers, automation, documentation, and decision-making. The missions gradually changed the way I look at technology because I learned not only how systems work, but also why they should be designed in a particular way.

During the early missions, I focused on understanding the basic concepts of cloud computing and the importance of organizing my work through GitHub. Creating a course repository helped me understand that version control is not only for programmers. It is also useful for documenting technical work, keeping track of changes, organizing activities, and making a project easier to review and maintain. The course also emphasized responsible use of AI, originality, proper citation, and meaningful authorship. This reminded me that tools can help me learn, but I still need to understand, check, and take responsibility for my own work.

Mission 3 helped me develop a broader view of cloud platforms. I explored AWS, Microsoft Azure, and Google Cloud Platform and compared their services, strengths, and possible business applications. I learned that choosing a cloud provider should not simply depend on which platform is most popular. The decision should be based on the actual needs of the organization, such as budget, existing technology, artificial intelligence requirements, Kubernetes, scalability, and global availability. Acting as a Cloud Solutions Consultant helped me start thinking from the client's perspective instead of choosing technology based only on personal preference. The mission also strengthened my research, comparison, documentation, and recommendation skills. fileciteturn0file1L85-L105

The containerization activities gave me more practical experience with Linux and Docker. I learned how to install and test Docker, work with images and containers, use persistent storage through volumes and bind mounts, connect containers through a custom network, and create a custom Docker image using a Dockerfile. These activities made the idea of containers more understandable because I was able to see their behavior directly instead of only reading about them. I also learned an important lesson about persistence: deleting a container does not necessarily mean that important data has to be lost when storage is designed properly. fileciteturn0file2L14-L44 fileciteturn0file2L82-L107

As the missions became more advanced, I became more comfortable working with Linux servers, networking, services, security, and automation. The later missions required me to combine knowledge instead of completing isolated exercises. This was one of the biggest changes in my learning. I had to troubleshoot problems, read documentation, understand error messages, and make decisions instead of simply following instructions. I realized that technical skills are not only about memorizing commands. A good cloud practitioner also needs patience, problem-solving skills, attention to detail, and the ability to recover when something does not work as expected.

Mission 10 was the point where all of these lessons came together. Instead of receiving a detailed step-by-step guide, I had to think like an Enterprise Cloud Architect. The final mission required a complete architecture with a Linux virtual machine, Docker and Docker Compose, a multi-tier application, persistent storage, firewall configuration, automation, backups or operational monitoring, and professional documentation. It also required the infrastructure to be defended live. This showed me that real cloud and infrastructure work is not about completing one command successfully. The whole system has to work together and remain secure, maintainable, and recoverable. fileciteturn0file3L31-L53

One of my biggest lessons from the final mission was the importance of security and reliability. The requirement to configure UFW with a default-deny policy made me understand that a working server is not enough. Unnecessary access should be restricted, and only required ports should be exposed. Persistent volumes showed me the importance of protecting data, while Bash scripts and Cron demonstrated how repetitive operational tasks can be automated. The final mission specifically required automation, security, persistent storage, and documentation, which made me see how these areas are connected in a real infrastructure environment. fileciteturn0file3L93-L137

Another important part of my journey was documentation. My GitHub repository became more than a place to submit files. It became a record of my progress and a technical portfolio. Markdown documentation, screenshots, source files, configuration files, and reflections helped me explain what I built and why I built it. By the end of the course, I understood why documentation is important for an IT professional: another person should be able to understand, deploy, maintain, and troubleshoot a system using the information provided.

Looking back at Missions 1 to 10, I can see a clear progression in my skills. I started by learning the concepts and vocabulary of cloud computing, then moved into comparing cloud platforms, working with Linux and containers, understanding storage and networking, applying security and automation, and finally designing and defending an integrated cloud infrastructure. The final mission required me to synthesize the concepts from the previous missions, which confirmed that each activity had a purpose in preparing me for the next level. fileciteturn0file3L93-L110

Overall, this course taught me that becoming a cloud professional is a continuous learning process. I still have many areas that I need to improve, especially troubleshooting complex infrastructure, security, automation, and cloud services. However, I now have a stronger foundation and more confidence in approaching technical problems. I learned to research before making decisions, test my configurations, document my work, protect my systems, and think about how different components affect one another.

The most important lesson I will take from Mission 1 to Mission 10 is that a cloud architect does not simply make technology work. A cloud architect designs systems with purpose, security, reliability, scalability, and future maintenance in mind. This journey has helped me move from simply following technical instructions toward understanding the reasoning behind infrastructure decisions. I believe this experience will be valuable not only for this course, but also for my future as an Information Technology professional.
